# Local skill quality audit — 2026-10-31

> **Pre-2.0.0 audit snapshot.** Local gaps, counts and line numbers below describe the original review. See the [filled matrix](GAP-MATRIX.md) for the implementation status and remaining evidence boundaries.

The marketplace package is structurally healthy, but the shipped reference material is not a complete, current API specification. The active skills correctly warn users to verify target-specific evidence. That safeguard does not fill the missing event sections, repair incorrect examples, or provide a measured completeness baseline.

This audit inspected maintained `skills/wow-*` content and the package validation/update implementation. References below use repository-relative paths and the line numbers observed during this audit. No existing skill files were changed by this review. Upstream observations below are scoped to Forever source commit `ca8368f2f2380cbe696854f7f2646387c278a61b`, version `1.60.1.70532`; they do not assert tested runtime availability.

The strongest existing guardrails should be preserved: explicit Retail/Forever/Classic selection, commit-pinned snapshots, historical provenance warnings, a distinction between source presence and addon permission, separate per-client artifacts, explicit offline/unknown behavior, and a client acceptance checklist. The updater proposes draft PRs, rejects incomplete source trees, and does not claim that CI substitutes for game-client tests.

## Specific source comparisons

Forever's damage-meter source defines `GetAvailableCombatSessions`, `GetCombatSessionFromID`, `GetCombatSessionFromType`, `GetCombatSessionSourceFromID`, `GetCombatSessionSourceFromType`, `GetSessionDurationSeconds`, `IsDamageMeterAvailable`, and `ResetAllCombatSessions`. The historical table instead lists `GetCurrentSessionID`, `GetSessions`, `GetSessionInfo`, `GetPlayerData`, `GetPartyData`, and `ResetSessions`. This is a source mismatch, not proof of universal removal of the old names. The session data methods also carry `SecretWhenInCombat` and `SecretArguments` annotations that must be preserved when promoting them into a current reference. [Pinned source](https://github.com/Gethe/wow-ui-source/blob/ca8368f2f2380cbe696854f7f2646387c278a61b/Interface/AddOns/Blizzard_APIDocumentationGenerated/DamageMeterDocumentation.lua#L8).

The event list also needs access-status reconciliation: `COMBAT_LOG_EVENT` and `COMBAT_LOG_EVENT_UNFILTERED` appear without payload/access context in [A–F](../../skills/wow-api-events/references/EVENTS-A-F.md), lines 492–493, while the combat historical baseline says they are unavailable to addons. A current ledger should resolve that discrepancy separately for each supported target, retaining evidence for both source existence and addon access.
