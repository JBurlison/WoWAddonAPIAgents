# WoW addon development

Follow the [addon-development workflow](../skills/wow-addon-development/SKILL.md) for every addon task. It defines research, implementation, packaging, and validation requirements.

For visible UI changes, follow its mock-up choice before implementation and its [UI testing guidance](../skills/wow-addon-development/references/UI-DESIGN-AND-TESTING.md). Respect an existing design preference. Follow [visual fidelity](../skills/wow-addon-development/references/VISUAL-FIDELITY.md): preserve the accepted artwork/style, use custom assets with native controls where needed, and compare actual screenshots before claiming a match. Use [Witchcraft MCP and computer use](../skills/wow-addon-development/references/CONNECTED-CLIENT-TESTING.md) when available; distinguish context/errors, visual results and real-client acceptance.

Use [client targets](../skills/wow-client-targets/SKILL.md) to resolve the requested clients before applying API guidance. Load the relevant domain skills linked by the workflow. Report evidence limitations and distinguish static checks from in-game testing.

This is the shared agent definition. Host adapters are generated from it; the workflow skill remains the Codex entrypoint.
