All three declare `C_GamePad.IsEnabled()` returning a boolean, `GetActiveDeviceID()` returning a number, and `GetAllDeviceIDs()` returning a number table. `GAME_PAD_ACTIVE_CHANGED` carries `isActive`; connected/disconnected declarations have no listed payload. Those declarations do not prove addon event registration/delivery or physical-device availability.

All three mark `EnableGamePadButton(enable)` and `EnableGamePadStick(enable)` protected, with a boolean argument defaulting to false. Forever/Retail add `SecretArguments = NotAllowed`; the inspected Classic declarations omit that field. Mouse simulation is limited to hardware input and eligible mouse-focus frames in all three inspected declarations. Verify callback signatures and access separately using the [API index](../../wow-api-index/SKILL.md).

Forever's [ClassActionFlyout](https://github.com/Gethe/wow-ui-source/blob/9dc84f0d3bbae1768ac3405b3716000bd93eda06/Interface/AddOns/Blizzard_GamepadActionBars/ClassActionFlyout.lua), loaded by the [camelot action-bar owner](https://github.com/Gethe/wow-ui-source/blob/9dc84f0d3bbae1768ac3405b3716000bd93eda06/Interface/AddOns/Blizzard_GamepadActionBars/Blizzard_GamepadActionBars.toc), documents that gamepad button-down capture blocks input and release goes to the capturing frame. This supports testing capture/release ownership; its native secure click implementation is not an addon recipe.

The inspected Retail and Classic trees do not contain Forever's `Blizzard_GamepadSmartNavigation`, `Blizzard_GamepadSharedUtility`, or `Shared/InputIcons/InputIconTexture.lua` paths. Their presence in Forever and a shared `C_GamePad` namespace do not establish equivalent native focus integration on other targets. Treat that Forever-specific integration as unavailable there; independently verify an ordinary-UI or cursor alternative.
