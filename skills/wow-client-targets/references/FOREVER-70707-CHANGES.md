# Forever 1.60.1.70707 source changes

Reviewed 2026-11-03: **1.60.1.70532** (`ca8368f2f2380cbe696854f7f2646387c278a61b`) → **1.60.1.70707** (`aff0d8cd53bf4d9ef1c1dd2786b94461a276fb16`). The [source comparison](https://github.com/Gethe/wow-ui-source/compare/ca8368f2f2380cbe696854f7f2646387c278a61b...aff0d8cd53bf4d9ef1c1dd2786b94461a276fb16) contains 118 relevant files, including nine generated API definition files. Retail 12.1.5.70688 and Classic progression 5.5.4.70631 remain at their existing pins.

These are declaration and loaded-source observations. Interface 16001 remains derived and requires confirmation in the client. No addon access, event delivery or visual behavior was tested in game. The packaged ledgers preserve complete typed contracts; this guide records migration implications and handwritten UI changes that the generated API inventory cannot express.

[GamepadActionBars' TOC](https://github.com/Gethe/wow-ui-source/blob/aff0d8cd53bf4d9ef1c1dd2786b94461a276fb16/Interface/AddOns/Blizzard_GamepadActionBars/Blizzard_GamepadActionBars.toc) is Camelot-only and depends on `Blizzard_GamepadSharedUtility` and `Blizzard_Gamepad`. Test the initial query, pending/cleared transitions and teardown in the intended addon context.

## Bag and item-button helpers

At this pin, [`ContainerFrameItemButtonMixin:Initialize`](https://github.com/Gethe/wow-ui-source/blob/aff0d8cd53bf4d9ef1c1dd2786b94461a276fb16/Interface/AddOns/Blizzard_UIPanels_Game/Mainline/ContainerFrame.lua#L1857) takes **`containerFrame, bag, slot`** instead of the older `bag, slot`, and retains the container owner. The new `IsCombined()` uses that owner. Addons that reuse or hook this Blizzard mixin must preserve the added argument and owner lifecycle instead of copying the old call shape. These are Lua helper contracts, not generated native widget methods.

[`ContainerFrame.xml`](https://github.com/Gethe/wow-ui-source/blob/aff0d8cd53bf4d9ef1c1dd2786b94461a276fb16/Interface/AddOns/Blizzard_UIPanels_Game/Mainline/ContainerFrame.xml#L153) removes `ItemSlotBackgroundCombinedBagsTemplate` from this source file and adds `EmptyBagIcon`. The shared [ItemButton XML](https://github.com/Gethe/wow-ui-source/blob/aff0d8cd53bf4d9ef1c1dd2786b94461a276fb16/Interface/AddOns/Blizzard_ItemButton/Shared/ItemButtonTemplate.xml) adds a mask and a `PostOnLoad` postcall; its [shared mixin](https://github.com/Gethe/wow-ui-source/blob/aff0d8cd53bf4d9ef1c1dd2786b94461a276fb16/Interface/AddOns/Blizzard_ItemButton/Shared/ItemButtonTemplate.lua#L16) masks normal, pushed and icon textures. The [Mainline helper](https://github.com/Gethe/wow-ui-source/blob/aff0d8cd53bf4d9ef1c1dd2786b94461a276fb16/Interface/AddOns/Blizzard_ItemButton/Mainline/ItemButtonTemplate.lua#L66) now returns the fallback from `GetItemButtonBackgroundTexture(button)` and restores texture coordinates when setting item textures. Recheck custom skins, empty slots, combined bags and inherited masks against the approved UI mock-up.

Loading matters: [UIPanels_Game's TOC](https://github.com/Gethe/wow-ui-source/blob/aff0d8cd53bf4d9ef1c1dd2786b94461a276fb16/Interface/AddOns/Blizzard_UIPanels_Game/Blizzard_UIPanels_Game.toc#L118) selects the Mainline container implementation plus Camelot overrides and the family XML. It depends on FrameXML, whose [TOC](https://github.com/Gethe/wow-ui-source/blob/aff0d8cd53bf4d9ef1c1dd2786b94461a276fb16/Interface/AddOns/Blizzard_FrameXML/Blizzard_FrameXML.toc#L7) depends on ItemButton. The [ItemButton TOC](https://github.com/Gethe/wow-ui-source/blob/aff0d8cd53bf4d9ef1c1dd2786b94461a276fb16/Interface/AddOns/Blizzard_ItemButton/Blizzard_ItemButton.toc) orders shared Lua/XML before the Mainline family implementation. Do not infer availability from a template's filename or carry its internal appearance into a custom UI without visual testing.

## Gamepad navigation and other loaded helpers

[Blizzard_GamepadSmartNavigation's TOC](https://github.com/Gethe/wow-ui-source/blob/aff0d8cd53bf4d9ef1c1dd2786b94461a276fb16/Interface/AddOns/Blizzard_GamepadSmartNavigation/Blizzard_GamepadSmartNavigation.toc) depends on SharedXML, allows both Game and Glue loading, and now loads `SecureHelper.lua` before Utility and SmartNavigation. The [new helper](https://github.com/Gethe/wow-ui-source/blob/aff0d8cd53bf4d9ef1c1dd2786b94461a276fb16/Interface/AddOns/Blizzard_GamepadSmartNavigation/SecureHelper.lua#L26) defaults to allowing secure callers or calls without an active `Enum.AddOnRestrictionType.Combat` restriction. That is not an unconditional out-of-combat permission rule: allowed keys, per-operation validation, secret rejection and callback taint still apply. Do not write its internal frame fields directly as a workaround.

The [Utility definitions](https://github.com/Gethe/wow-ui-source/blob/aff0d8cd53bf4d9ef1c1dd2786b94461a276fb16/Interface/AddOns/Blizzard_GamepadSmartNavigation/Utility.lua) change or add these global helpers:

| Lua helper | Contract observed in the implementation |
|---|---|
| `SmartNavigation_MarkFrameIgnored(inFrame, dontPropagate)` | Adds `dontPropagate`; truthy selects the non-propagating flag rather than ignoring descendants. |
| `SmartNavigation_GetDirectionBufferThreshold(inFrame, direction)` | Returns the stored threshold or nil; the setter converts input degrees to radians, so the returned stored value is not degrees. A valid direction object supplies `dirKey`. |
| `SmartNavigation_ClearDirectionBufferThresholdInDirection(inFrame, direction)` | Clears one direction through the guarded setter; returns early for missing frame/direction. |
| `SmartNavigation_ClearDirectionBufferThresholds(inFrame)` | Clears each defined direction through that helper. |
| `SmartNavigation_GetCustomCursorAnchorPointForFrame(inFrame)` | Returns a constructed anchor, or nil when no anchor point is recorded. |
| `SmartNavigation_ClearOutgoingNavigationCallbacks(button)` | Clears each directional callback collection through the helper; missing button returns early. |

[`SmartNavigationMixin:SetGridHeightCompensation(inFrame, shouldCompensate)`](https://github.com/Gethe/wow-ui-source/blob/aff0d8cd53bf4d9ef1c1dd2786b94461a276fb16/Interface/AddOns/Blizzard_GamepadSmartNavigation/SmartNavigation.lua#L1058) is new. `SetTargetButtonForFrame(inFrame, inTargetButton)` and other setters now use the secure helper's wrapper. The same file marks `SelectButton` internal and secure-only. Older `SetReturnFrameFocusButton`, `SetNavigationFunction`, `CanNavigateToButton`, `SetIsHandlingInputEvents` and `NavButtonMixin` definitions disappear from these implementations; do not present them as current APIs or infer universal removal from all clients. Validate the specific loaded helper and caller context before using it.

[`Menu.IsMenuProxy(frame)`](https://github.com/Gethe/wow-ui-source/blob/aff0d8cd53bf4d9ef1c1dd2786b94461a276fb16/Interface/AddOns/Blizzard_Menu/Menu.lua#L2762) is new and returns whether `frame.isMenuProxy == true`. The [Menu TOC](https://github.com/Gethe/wow-ui-source/blob/aff0d8cd53bf4d9ef1c1dd2786b94461a276fb16/Interface/AddOns/Blizzard_Menu/Blizzard_Menu.toc) loads the implementation for both environments and selects Camelot-specific XML. Menu resetters now invoke their callbacks through `securecallfunction`; this does not grant arbitrary callbacks secure authority.

The [PvPMatch TOC](https://github.com/Gethe/wow-ui-source/blob/aff0d8cd53bf4d9ef1c1dd2786b94461a276fb16/Interface/AddOns/Blizzard_PVPMatch/Blizzard_PVPMatch.toc) permits standard/Camelot, is not load-on-demand, and now selects dedicated Camelot result and scoreboard Lua/XML plus a table override before its XML. Recheck hooks, child-frame paths and layout against the selected implementation instead of assuming Retail internals from shared frame names.
